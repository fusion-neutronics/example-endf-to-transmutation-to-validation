# this wheel puts an `njoy` in the venv's bin/. Use your own build instead with
# `--njoy`, which is also how you point at the IAEA-NDS fork that FENDL needs.
--extra-index-url https://shimwell.github.io/wheels
njoy2016

# yani reads the nuclear data and now makes it too: the ENDF conversion, the
# reaction topology and the isomeric branching are all functions on the wheel.
# Nothing here resolves against a sibling checkout, there is no `endf` package
# pinned to a branch of a fork, and nothing is installed from git.
#
# `yani` is a small distribution that pins the compiled `yani-core` wheel and
# pulls it in; the module you import is `yani` either way (as `pillow` provides
# `PIL`). Wheels are published for Linux x86_64, Windows x64 and macOS arm64,
# abi3 from Python 3.10 up, so there is nothing to build.
#
# The floor buys thirteen things, all of them load-bearing here:
#
#   * `TransmutationChain.decays` (0.8), so make_report.py can follow a
#     production route past its neutron reaction. Without it a route stops at
#     the first product and the decay steps that carry it on, which is most of
#     what a pathway analysis is, cannot be derived at all.
#   * `TransmutationResults.step_materials` (0.9.0), which run_transmutation.py
#     calls since `Material.transmute` stopped returning a plain list. Against
#     0.8 that fails with `AttributeError: 'list' object has no attribute
#     'step_materials'`, minutes in, after NJOY has already done its work.
#   * `TransmutationResults.get_reaction_rates` (0.9.0), the per-edge rates the
#     Path % column is computed from.
#   * `convert_neutron_xs(covariance=True)` (0.11.0), which writes the MF=33
#     cross-section covariance beside each nuclide. Older wheels take no such
#     argument and raise on it, in step 1, before any NJOY time is spent.
#   * `DataUncertainty` (0.11.0), which resamples the activation cross sections
#     from that covariance, folds each draw against the foil's own spectrum and
#     re-solves. That is the "+/- 6%" on the calculated column and the %dCnuc
#     beside it, the last two columns of the published tables this example
#     could not fill.
#   * `TransmutationResults.get_decay_heat_uncertainty` (0.12.0), which takes
#     the spread of that ensemble over whole inventories. Step 2 used to do it
#     by hand, rebuilding a Material per replica out of
#     `get_uncertainty_inventories` and calling `np.std(..., ddof=1)` on the
#     totals. yani computes the same statistic with the same divisor, per
#     replica and per nuclide, and does not pay for a Python object per draw.
#   * `yani.data.split_nuclide` (0.12.0), which convert_to_arrow.py names TENDL
#     files with. Stripping the digits off "Ta180_m1" leaves "Ta180_m" and a
#     mass number of 1, and natural tantalum really does contain Ta180m, so
#     this used to be a splitter kept here purely to avoid that.
#   * `TransmutationResults.get_production_routes` and
#     `get_isomeric_branching` (0.13.0), which make_report.py's pathway page is
#     built from. Both used to be derived here: the routes by walking the chain
#     from the foil's isotopes and weighting them out of the per-edge rates,
#     which was 500 lines and needed the chain loaded a second time, and the
#     branching by taking ratios within a channel's edges. yani answers both
#     from the chain and the rates the solve actually ran with.
#   * `data_uncertainty_info["rate_fraction_covered_total"]` (0.13.0), the share
#     of the production the covariance spans. This was folded here out of
#     `rate_fraction_covered` and the edge rates, joined on a string key, and
#     weighted by rate but not by the density of the parent each rate belongs
#     to, which is a factor of three wrong on iron.
#   * `get_isomeric_branching` returning a list of channels ordered by
#     production (0.15.0), which make_report.py's branching block reads
#     straight through. Against 0.13.0 it is a dict keyed by parent, which the
#     block now refuses rather than mis-reads, and the ordering was done here
#     too: an edge rate is per atom of its parent, so on rate alone
#     `W180(n,2n)` outranks `W186(n,2n)` on a tungsten foil and W180 is 0.12%
#     of it.
#   * A chain built for a different foil is refused by `transmute` (0.13.0)
#     rather than solving to an inventory of nothing. run_transmutation.py used
#     to write a `scope.json` sidecar beside each chain and check it itself.
#   * The `data_version` the published libraries carry (0.16.0). This is the
#     one entry that is not about a function. Every wheel pins the release it
#     expects and refuses a download that reports another one, so the wheel and
#     the data move together and a floor on the wheel is a floor on the data.
#     All six libraries were republished on 2026-09-08. 0.14.0 expects
#     2026-08-21 and 0.15.0 expects 2026-09-02, so both refuse the endf-b8.1
#     decay sublibrary step 2 fetches, and they refuse it in the first seconds
#     of a run rather than serving something stale.
#   * `decay_energy_placeholders` and `decay_inconsistencies` in that
#     sublibrary's `provenance.json`, which the 2026-09-08 rebuild is the first
#     to carry and make_report.py's nuclear data page now reads. Decay heat is
#     a sum over products of N x lambda x Q, and endf-b8.1 is what sets lambda
#     and Q here, so a product whose average decay energies are the Q/3 stand-in
#     rather than an evaluated scheme is carrying a placeholder straight into
#     the answer. 1144 nuclides are on that list, and the page names the ones a
#     foil's heat actually runs through instead of leaving them to be found.
#
# 0.16.0 for both names: `yani` 0.16.0 pins `yani-core==0.16.0`, so the wrapper
# and the compiled wheel move together and a floor on the one is a floor on the
# other. 0.15.0 was never published to PyPI, so the previous floor resolved to
# 0.16.0 anyway; what it did not do is say why nothing earlier will serve, which
# is now a statement about the data and not only about the API.
#
# A floor turns each of those into an unsatisfiable requirement pip reports up
# front, rather than an AttributeError partway through a run.
yani>=0.16.0
